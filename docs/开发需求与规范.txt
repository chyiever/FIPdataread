第一部分　开发需求
================================================================================

一、数据格式

  数据格式为 npz，示例数据位于 E:\codes\FIPread\data，文件内容格式如下：

  {'file_path': 'D:\\PCCP\\FIPdata1\\phase_data_20260320_203743_045_#002299.npz',
   'comm_count': 2299,
   'timestamp': 0.0,
   'sample_rate': 200000.0,
   'length': 2000000,
   'duration_seconds': 10.0,
   'min': 2786.522431458737,
   'max': 2841.4097103954286,
   'mean': 2802.8608909485893,
   'std': 14.041409719537286,
   'data_info': {'type': 'phase_unwrapped_downsampled',
    'length': 2000000,
    'downsample_factor': 5,
    'packet_count': 50,
    'start_comm_count': 2250,
    'end_comm_count': 2299,
    'duration_seconds': 10.0,
    'save_time': '2026-03-20T20:37:43.045121',
     'phase_data': .........
  }

二、功能需求

  使用 Python 3.9 + PyQt5 编写数据读取绘图分析软件（FIPread），具有以下功能：

  1. 输入一个路径，软件 UI 显示该路径下所有文件名，每次显示 30 个，以 30 个文件作为
     单位，可点击“下30个”按钮进行切换文件名。

  2. 点击左侧文件名列表中的任意一个文件，右侧显示该数据的时域波形图。

  3. 时域波形绘图的要求：
     （1）横轴时间（时:分:秒.毫秒）、纵轴相位（单位 rad）
     （2）纵轴的刻度范围可自动，也可手动调整，例如在 UI 中输入 -1、1，则设置
         ylim([-1, 1])
     （3）时域波形支持矩形放大、复原等鼠标互动功能
     （4）信号的采样率在 100 kHz 数量级，单个数据文件 1 分钟（典型值），因此需要
         采用高效的算法保证绘图效率。

  4. 支持对时域波形进行滑窗截取，并对短窗信号计算 PSD，并自动进行绘图（横轴频率、
     对数形式，纵轴 PSD 单位 dB，图位置在时域图下方），可使用 welch 函数。滑窗截取
     短窗信号的方式：鼠标右击表示短窗开始，鼠标向右/左移动，到达想要的位置后鼠标松开，
     则完成短时窗的截取，随即自动计算 PSD 并绘图显示。完成滑窗后，可对属于信号中的
     短窗信号添加黄色阴影。

三、开发要求

  1. 软件开发需遵守软件工程相关规范，模块化编程，分级写注释，注重算法的可移植性和
     可维护性，读取大量数据时软件应具有较高的数据处理效率。

  2. UI 中英文全部使用新罗马字体，中文使用宋体。

  3. 图的刻度、标签全部使用英文、新罗马字体，刻度字号要大。

  4. 创建 docs 子文件夹，存储开发过程中的技术文档，以 md 格式介绍软件的功能介绍、
     实现逻辑、使用的关键库/函数/控件等，记录开发过程中遇到的问题，记录解决方案。

  5. 创建 scripts，存储相关代码，注意模块化编程，相同功能的代码不要重复出现，代码
     尽可能简单轻便。


================================================================================
第二部分　软件开发中颜色、色系及色调要求
================================================================================

一、核心原则

  • 可用性：颜色需清晰可辨，按钮、文本、背景的颜色对比需达标；
  • 一致性：同一功能、同一模块的颜色需统一；
  • 简洁性：整体色系不超过 3-4 个主色系，辅助色不超过 5 个，避免颜色杂乱影响视觉体验。

二、色系选择要求

  • 专注、高效，减少视觉干扰，突出功能模块，适合低饱和度、高对比度的色系。
  • 主色系：优先选择中性色（灰色系、白色系）搭配低饱和辅助色，如浅灰（背景）、
    深灰（文本）、蓝色系（主功能按钮）。

三、色调规范

  “统一色调、分层适配”

  （一）通用色调要求

  1. 明度分层：背景色（明度最高）→ 文本色（明度中等/偏低，与背景形成高对比）→
     功能按钮（明度中等，与背景有明显区分）→ 强调元素（明度偏低/偏高，突出重点）；
  2. 饱和度控制：主色饱和度控制在 40%-70%，辅助色饱和度控制在 30%-60%，背景色饱和度
     控制在 0%-20%，避免高饱和颜色堆积；
  3. 色相对比：相邻元素（如文本与背景、按钮与背景）的色相对比需清晰，避免同色系、
     同明度的颜色叠加（如浅灰文本 + 浅灰背景）；
  4. 深浅适配：同一颜色需设计 3-5 个深浅梯度（如主色的浅、中、深版本），用于 hover、
     选中、禁用等状态（如按钮默认用中色，hover 用深色，禁用用浅色）。

  （二）色调适配

  浅背景用高明度、低饱和度颜色（如白色、浅灰），文本用低明度、低饱和度颜色（如深灰、
  黑色），按钮用中明度、中饱和度主色，整体色调明亮、清晰。

四、补充说明

  • 颜色取值：建议使用十六进制（如 #FFFFFF）、RGB（如 rgb(255,255,255)）或 RGBA
    （带透明度，如 rgba(255,255,255,0.8)）取值，确保不同开发环境下颜色一致；
  • 透明度规范：透明度控制在 0.1-0.8 之间，避免透明度过低导致颜色模糊，过高导致与
    背景混淆；
  • 避免使用单一颜色贯穿整个界面（如全红、全蓝背景）；
  • 避免高饱和撞色（如红+绿、黄+紫）；避免颜色含义冲突（如绿色代表“确认”）；
  • 避免使用难以区分的颜色；禁用过于刺眼的颜色（如亮黄色、荧光色）。

第三部分　软件开发优化指令
================================================================================

（1）上传当前版本（除数据外的代码）至 github main 分支，commit：add t-f plot, UI layout。

（2）专门编写 README-DATA-Structure.md，介绍软件现在兼容读取的数据类型，尤其是每种格式的
    数据结构、文件名是否有要求、导出的数据格式/结构/文件名默认规范、导出的音频文件
    格式/结构/文件名默认规范。

（3）导出数据时，现在导出的是 tdms。请增加一种选项：npz。可在下列列表中选中输出文件的
    格式，默认 npz。导出的 npz 结构与软件读取的 npz 结构类似（包括 phase_data、sample_rate、
    starttime、npts 等，starttime 即文件名时间，npts 代表该文件中总的采样点数）。下拉列表
    可放在 refresh 按钮右侧。

（4）增加功能：手动在图中标记初至（标记振动信号到达时刻）。
    交互方式：
      1. 键盘按住 ctrl，同时鼠标右击，则时域图中出现一条蓝色竖线，定义该线对应的时刻为
         振动信号到达时刻；
      2. 出现蓝色竖线后，键盘按住 ctrl 同时点击键盘向左/向右的箭头，蓝色竖线左右移动，
         移动步长为 0.3 ms。
    标记初至后，在最下方状态栏显示标记的初至时间，例如：First arrival time。
    导出当前显示的波形至本地时，在 npz 结构中添加"arrival_time"一项。如果有标记初至
    时间，则将初至时间存储到 npz 文件中，例如："arrival_time"：20260304155621.2333，
    精确到 0.0001 s。如果没有标记，则存储 None 或空着。
    读取一个 npz 文件时，在最下方状态栏显示该数据文件的采样率、arrival_time、总时长
    （单位 s）等头文件信息。
    完成后，编写 2026-04-15-初至时间标记.md。

（5）增加功能：标记信号窗样本类型。
    手动标记该信号窗的样本类型（从下拉框里选择，鼠标放到大类标签选项中时，弹出小类选项
    框；也可以手动输入）。
    在"Files management"参数框中添加一个下拉列表兼输入框，即可从列表中选择样本类型，
    又可手动输入；若为空，则不标记。

    样本类型分为五大类：
      第一大类：断丝。格式：BK + PCCP 管内径（单位分米）。细分 BK14、BK12、BK40 三种。
      第二大类：平稳的流噪声。格式：F + 流速，细分 F0、F052、F065、F130 四种。
      第三大类：非平稳的流噪声。格式：F + 流速 + a/b/c…，细分 F0a、F052a、F065a、
              F130a 四种。
      第四大类：锤击。格式：HM + PCCP 管内径（单位分米），细分 HM12、HM14 两种。
      第五大类：其他。代码：OT。

    导出当前正在显示的时域信号窗的原始信号到本地（该功能已有）时，在导出的 npz 文件
    结构中添加 type，其值为样本类型代码（若未标记，赋值为 None 或不赋值）（同步更新
    README-DATA-Structure.md）。

    如果没有标记信号窗样本类型，导出到本地的文件名规范不变，依然例如：
        FIP-200K-20260323T103125.631.npz
    如果标记了信号窗样本类型，导出到本地的文件名规范为：样本标签 + ……，例如：
        BK-FIP-200K-20260323T103125.631.npz

（6）制作样本目录。如果标记了信号窗样本类型，导出原始数据到本地的同时，制作样本目录表格
    （如果已有，在已有文件内补充）。表格各列含义：
        样本类型（编码，例如 BK14）+ 文件起始时间（格式：）+ 信号初至时刻（格式：，
        如果没有到时，则该项为文件起始时间）+ 文件时长（单位 s）+ 数据采样率（单位 kHz）
        + 样本 ID。
    样本 ID 为：样本类型编码 + "-" + 信号初至时刻（格式：，如果没有到时，则该项为文件
    起始时间），例如 BK14-260327-152715.000。
    注意目录表格中各列的宽度足够，保证阅读时每列内容显示全。
